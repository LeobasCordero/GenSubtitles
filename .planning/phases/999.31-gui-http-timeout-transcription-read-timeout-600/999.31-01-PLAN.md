<objective>
Fix the GUI `ReadTimeout` crash by changing the flat 600-second timeout in `_run_step_in_bg` to a split connect/read timeout of `(5, None)`.

Purpose: The blocking `/steps/transcribe` HTTP call uses `timeout=600`, which fires when transcription of a long video exceeds 600 seconds. Changing it to `(5, None)` keeps the 5-second connect timeout (so "server not running" is caught quickly) while removing the read timeout entirely — matching the existing pattern in `_run_sse_flow`.

Output: Single-character change in `gensubtitles/gui/main.py`, tested via the existing test suite.
</objective>

In `gensubtitles/gui/main.py`, inside the `_run_step_in_bg` method's inner `_worker()` function, change:

```python
resp = req.post(f"{server.BASE_URL}{api_endpoint}", json=payload, timeout=600)
```

to:

```python
resp = req.post(f"{server.BASE_URL}{api_endpoint}", json=payload, timeout=(5, None))
```

`(5, None)` means:
- `5` = connect timeout in seconds (fails fast if server is not running)
- `None` = no read timeout (allows transcription to run as long as needed)

This is the same pattern already used by `_run_sse_flow`'s stream request:
`timeout=(5, None)  # fail fast if server unreachable; keep stream reads unbounded`

No other changes. Do NOT modify error handling, method signatures, or any other code.
